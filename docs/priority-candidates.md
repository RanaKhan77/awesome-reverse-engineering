# Priority-candidate source review

Reviewed on **2026-10-13 UTC**, following [research issue #6](https://github.com/morluto/awesome-reverse-engineering/issues/6). This intake adds the 23 A0/A1 resources to the 116-entry baseline, for 139 catalog entries.

The review used three passes: canonical repositories and pinned source snapshots; task/claim/host/target/license scrutiny; then the final catalog diff, examples, and link checks. All 22 GitHub repositories were rechecked as unarchived and enabled. JEB was reviewed through the vendor product page, manual, and changelog.

**Reproduced** means only the bounded case described in [the examples](../examples/resource-intake/README.md), not the full upstream support matrix. Four resources have this status. The other nineteen are **documented**; hardware, iOS-device, commercial-tool, and browser-agent behavior was not executed. Recent commits, HTTP success, and SPDX metadata alone do not establish quality or compatibility.

The [machine-readable snapshot](priority-candidates.json) retains source revisions, activity/release observations, constraints, evidence scope, and a next review date of **2026-11-13**. GitHub license metadata is preserved as an observation, not a complete license audit. The earlier comparison in `list-review.md` remains a historical snapshot.

## Corrections made during intake review

Pinned source links use the same immutable GitHub files through `raw.githubusercontent.com`, avoiding intermittent 503 responses from GitHub HTML rendering. The JSON retains the corresponding browser URLs as well as the source revision; resource entry links still point to canonical repositories.

- wasm-tools declares Apache-2.0, Apache-2.0 with LLVM exceptions, and MIT licenses in its pinned README. The earlier research shorthand of Apache-2.0 alone was incomplete; the GitHub SPDX observation and the source declaration remain separate.
- Facedancer explicitly identifies GNU/Linux host support, incompatible legacy scripts, and board/backend limits; the catalog now states these instead of a vague version caveat.
- IDA MCP requires IDA 9.4+ with idalib, Python 3.11+, and uv. The MIT server is distinct from licensing the required IDA host. Chrome DevTools MCP states Node LTS and Chrome requirements.
- checksec is described as ELF-property triage rather than a general vulnerability verdict. Source-build dependencies for other tools are recorded here without imposing them on users of prebuilt releases.
- JEB headless MCP appeared in 5.41, and `run_apk_analysis` in 5.47; the reviewed changelog is 5.48. These dates do not imply that all MCP capabilities arrived together or exist in every edition.
